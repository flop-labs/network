### Added

- `flop validator join` accepts `--p2p-port` and `--da-port` with compatible signing bundles.
  The default public TCP pair is 30333 and 7001.

### Changed

- Clarified Testnet gateway access in the setup guide and credential help. Use an existing Testnet
  key when `/v1` omits `wallet_enrollment`. Claiming faucet funds does not issue a gateway key.

- Testnet faucet receipts show the reward rules and the recipient's inference spend link when supplied.

- When the Testnet faucet's `/limits` puts the next free room of a full cap within a minute, or in
  the past, `flop faucet request` now says room frees continuously but other clients take it as it
  frees, with `retry_after_seconds: 60` and a `next` of "retry in a minute or more, not in a loop",
  instead of a clock time seconds away. `next_free_at` stays the faucet's time.
- On Testnet, the `FAUCET_NOT_OPEN` refusal from `flop faucet request` is now `retryable: true`,
  and it adds `retry_after_seconds` and `next_free_at` when the faucet reports them. Its `next` is
  the exact retry command. A `/limits` that answers 503 `warming` keeps the code
  `FAUCET_UNAVAILABLE`, but now says the faucet is starting, carries `retry_after_seconds` from
  its Retry-After and is `retryable: true`; with `--nonce` it is unchanged. A claim refused with
  `daily_cap` because the shared limit filled after `/limits` was read stays `RATE_LIMITED` but is
  now `retryable: true`. The per-wallet `agent_daily_cap` refusal is unchanged.
- `flop miner declare-gpu` publishes a `flop.gpu-inventory.v2` remark, which adds each GPU's PCI
  device ID. `--nvidia-smi` now needs the output of
  `nvidia-smi --query-gpu=name,memory.total,pci.device_id --format=csv,noheader,nounits`; a
  two-column file is refused. `--detect` runs that query itself instead of the SDK's GPU detection.
  `--retract` publishes an empty v2 list.

### Fixed

- On Testnet, `flop faucet request` no longer reports a full shared limit as a faucet that is
  not open. With `daily_cap_reached` the message says the faucet is funded, that its shared limit
  per rolling 24 hours is full, and when the next room frees, from `/limits`
  `faucet.dailyCap.nextFreeAt`. Faucets that do not send that field get "retry later".
  `low_balance`, `unknown` and `warming` now say what each means. A claim that races a filling
  limit gets the same explanation, with the faucet's Retry-After.
