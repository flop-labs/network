### Added

- `flop agent-key create|status|revoke|drain`: a capped session key restricted to
  `ComputeChannel` whose owner is a fresh, dedicated funding account, never the main wallet.
  `create` checks every amount exactly against chain bounds (`MaxSessionDuration`, the session
  circuit breaker, the existential deposit), writes the funding account's scrypt-encrypted keystore
  and the delegate seed (secret store, `<network>/agent-key/<name>`) before anything goes on chain,
  then funds the account from `--keystore`, creates the session and funds the delegate's fees, each
  signed against finality, recorded before broadcast and awaited to finality. An existing name is
  refused; `--resume` continues from finalized state and never resubmits a transaction that may
  still land. `revoke` marks the key revoked locally, revokes on chain, confirms at finality and
  only then deletes the seed; `drain` returns the funding balance with `transfer_all` only while
  holding the spend-journal lock and once no spend is unresolved and every channel is closed.
- `loadAgentKey` (`commands/agent-key-lane.ts`) for launchers: a `SessionChainSubmitter` for the
  funding account plus a `beforeSpend` hook that refuses once the key is revoked locally, its
  session is revoked or expired at finality, or the funding account holds forward rights.
- `flop launch claude|codex --pay wallet|agent-key|api-key`. Without `--pay` the trial lane is
  unchanged. `wallet` (explicit `--keystore` + `--password-env`) and `agent-key` buy a long paid
  session to one miner (`--miner`, `--endpoint`, `--model`, `--budget-flop`, `--max-channel-flop`,
  `--top-up-flop`, `--window-hours`, `--max-lock-hours`, `--max-tokens`, plus `--enclave-key` or
  `--indexer`). `api-key` forwards to the gateway with a key from the secret store. Both run
  behind a loopback proxy (`/v1/messages`, `/v1/responses`, `/v1/chat/completions`,
  `/v1/models`) with a per-run token: the agent child gets only the proxy URL and that token, in
  an allowlisted environment and without a shell. Direct turns stream text live and release tool
  calls only after the stream matches the signed receipt; a retried request replays instead of
  buying again. `--recover` reconciles the journal and submits `computeChannel.timeout` for
  orphaned channels whose window has passed at finality.
- `flop gateway-key set|status|delete [--name]`: checks a gateway key with `GET /v1/keys/me`
  and keeps it in the OS keychain (or `--secret-store file`) under `<network>/gateway-key/<name>`.
  The key is read from stdin (hidden on a terminal) or `--from-env`, and never printed.
- Secret store for durable agent and gateway keys (`secret-store.ts`): macOS keychain through
  `security -i` on stdin, Linux Secret Service through
  `secret-tool`, Windows DPAPI through one static PowerShell script, and an explicit plaintext
  0600-file backend. The secret never appears in a helper's argv or in an error, and a requested
  keychain that is unavailable fails instead of falling back to the file.
- Allowlisted child environment for agent processes (`child-env.ts`): the wallet password variable,
  `FLOP_SIGNER`, `FLOP_API_KEY`, provider API keys and secret-looking names are never inherited.
- `flop model preflight` accepts DeepSeek-V4.1-Flash-1017 and prints
  `metering: unverified-miner-computed`. Onboarding and release planning refuse any other revision or
  content root than the pinned one, and refuse its registration until a stored-tensor parameter
  census is reviewed.

### Fixed

- `flop agent-key revoke` no longer strands the delegate's unspent fee balance. After the
  revocation is final, the delegate signs `balances.transfer_all(funding, false)`, recorded as the
  `sweep` step. The seed is deleted only once the delegate holds less than the existential deposit
  at finality. A sweep that fails or has an unknown outcome keeps the seed, and a re-run continues.
  A missing seed with funds still on the delegate is reported, not marked deleted.
- `flop launch claude|codex --recover` without `--pay` infers the lane from the state directory
  that exists for `--agent-name` (`~/.flop/agents/wallet/<name>` or `~/.flop/agents/key/<name>`). It
  refuses when both exist or neither does. Before, it fell back to `--pay trial` and was refused.

- `flop launch claude|codex --pay wallet|agent-key` no longer sets effort `high`, whatever the
  model's catalog advertises: the miner's v2 codec rejects `reasoning_effort` unconditionally, so
  every turn failed. Codex now gets no effort; Claude gets `CLAUDE_CODE_EFFORT_LEVEL=auto`, which
  overrides your own `effortLevel` and sends none. Before any purchase, the proxy refuses with 400
  every control the miner's `flop.chat-turn.v2` codec rejects: an unsupported effort, `stop`,
  `seed`, penalties, `logit_bias`, `response_format`, a required or named `tool_choice`,
  `parallel_tool_calls: false`, strict tools and a `top_p` of 0. `developer` messages are sent as
  `system`.
- The direct proxy answers 413 before buying when a turn's hex-encoded miner body would pass the
  worker's 1 MiB limit. On a direct lane Claude starts with `--strict-mcp-config` by default.
  The new `--inherit-mcp` keeps your MCP servers (claude only).
- A miner's pre-serve refusal of a request, or a refused verified output, is cached per request
  identity, so the agent's automatic retry replays the error instead of buying a channel each time. A failed `/v1/responses`
  stream now ends in `response.failed`, which Codex acts on.
- `launch-lanes` unit tests redirect `USERPROFILE` as well as `HOME`, so `--recover` and the
  wallet journal path are tested in the temporary home on Windows too.
- `flop launch claude` and `flop launch codex` enroll through the purpose-bound tools lane that
  `flop hermes` uses, so the devnet key is scoped to a model whose live catalog record offers tools.
  Before, the key went to the catalog's first model, which may not offer tools, and the launcher's
  own capability check then refused it. A cached key for a model without tools now fails with both
  cache paths to move aside. Enrollment needs an operator-opened tools enrollment window.
- `flop launch --pay wallet|agent-key --recover` reads only the spend journal and finalized chain
  state: no live catalog, admitted miner, listed model, usable session or delegate seed. It works
  after the agent key is revoked or expired and after the miner or model is gone, and signs the
  permissionless timeouts with the wallet keystore, `--keystore`, or the agent key's funding
  account (`funding.json`, `--password-env`), loaded only when a timeout is due. Purchase options
  given with `--recover` are refused instead of ignored.
- `flop agent-key drain` reconciles the journal against finalized chain state first, so channels
  that closed on chain after the launcher stopped no longer block it; it still refuses on a spend
  that evidence leaves unresolved or a channel not closed at finality.
- Wallet-lane journals live under `~/.flop/agents/wallet/<name>/` and agent keys under
  `~/.flop/agents/key/<name>/`, so a wallet-lane journal is never mistaken for, or replaced by, an
  agent key of the same name.
- `--max-tokens` is refused on `--pay api-key`, where it was silently ignored.
- Paid-lane agents get `SSH_AUTH_SOCK`, `SSH_AGENT_PID`, `SSH_CONNECTION`, `SSH_TTY`, `GIT_*`,
  `EDITOR`, `VISUAL`, `PAGER`, `DISPLAY` and `WAYLAND_DISPLAY`, so git and ssh work inside them;
  secret-looking names, git's config injection variables and cloud credentials stay withheld.
