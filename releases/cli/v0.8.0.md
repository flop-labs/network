### Changed

- Requires `@flop-labs/sdk` 0.9.0, which admits devnet runtime `1014034`.
- `flop gateway renew --qualification-receipt` publishes an uploader's first tools qualification
  under the record's declared conformance window.

### Added

- `flop proxy` responses carry `X-Flop-Completion-Tokens-P50`, `-P90` and
  `X-Flop-Completion-Length-Source` from the shared completion-length predictor, as a `max_tokens`
  hint. The task's G_n budget is still sized by the request's `max_tokens`.
- `flop gateway renew --qualification-receipt` publishes a payer-funded static deployment
  qualification (`flop.static-tools-qualification.v1`, `verifyStaticToolsQualification`). The
  settled channel's miner and enclave key must match its served deployment descriptor and the
  probe start must fall inside the descriptor's interval. It publishes only with a confirmed served
  identity, which the renewer then certifies unpaid.
- `flop gateway renew` certifies a model's `tools` once per uploader qualification. Receipt-only
  publication (`--qualification-receipt`) of a qualification whose binding carries what the gateway
  observed the miner serving just before the turn (a channel-signed miner's v2 signed session info,
  or a bearer miner's authenticated `/session/info`, its hash in the miner-signed input), with the
  turn's signed render context, adds `served_identity` to the pass:
  measured root, worker image, inference backend build and chat profile, chat template and output
  parser. Direct runs keep it in `tools-certifications.json` beside `--out` and renew the
  declared-window pass, without paying, on every run that observes a miner serving that exact
  identity, with no timer. An observed identity change withdraws
  `tools` in the same run and stops earlier passes, uploader qualifications included, from carrying.
  Certifications from the earlier renewer-paid scheme renew only on their own miner, for seven days.
  A receipt-only append keeps an expired profile-bound first pass, and republishing a receipt first
  published without its served identity adds it.
- `flop model preflight` accepts Kimi-K3.1-Pro @ `d9e99b07` at its pinned content root and prints
  `metering: unverified-miner-computed`, sizing its throughput ceiling from reference completion work.
  Onboarding and release planning refuse its registration: its packed MXFP4 experts have no reviewed
  stored-tensor census, and its #4130 capture adapter is unqualified under an inactive execution profile.

### Removed

- `flop gateway renew` no longer opens paid probe channels: `--probe-signer-env`, `--probe-escrow`
  and `--probe-budget` are removed, along with the probe budget file format, random audits and
  failure backoff. The model uploader pays for `tools` conformance through
  `POST /v1/model-qualifications/tools`; a profile-bound feature's first pass comes from that
  qualification too.

### Fixed

- `flop launch --pay wallet` no longer leaves a channel for the timeout refund when the miner's
  cooperative close takes over 60 s: it waits for the miner's settlement to finalize, up to
  10 minutes, and says on exit that settling can take several minutes.

- `flop gateway renew --qualification-receipt` counts a fee-profile channel's `ValidatorFeeAccrued`
  in the canonical payment and debit, so a qualification settled on such a channel publishes
  instead of failing the debit check.
- `flop gateway renew` (direct probe mode) signs each budgeted probe submission with a mortal era
  born at the finalized head (`FlopChainSubmitter.prepare`) instead of polkadot-js defaults, which
  could birth the era at a best-block parent that was later reorged away and get the extrinsic
  rejected with `1010: Invalid Transaction: Transaction has a bad signature`, leaving the probe
  budget ambiguous and its lock held. Signing now happens before the reservation is persisted, so
  a signing refusal (stale or lagging finalized head) reserves nothing and releases the lock.
