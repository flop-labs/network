### Changed

- `get_wallet_info`, `get_agent_wallet`, `get_total_wallets` and `get_owner_wallet_count` now
  raise when the storage query fails instead of returning `None` or `0`. A wallet that does not
  exist still reads as `None`.
- `FlopClient.submit_poui`, `get_compute_task` and `get_tee_quote` raise
  `FLOPError(code="RPC_METHOD_UNAVAILABLE")` without sending a request. No FLOP node serves
  `poui_submitStarkBatch`, `hasStation_getTask` or `tee_getQuote`, so these calls always failed
  with `-32601`.

### Fixed

- AgentWallet extrinsic wrappers in `flop_sdk.agent_wallet` and `flop_sdk.substrate` use the
  runtime's call names (`create_wallet`, `fund_wallet`, `agent_transfer`, `owner_withdraw`,
  `deactivate_wallet`, `reactivate_wallet`); the camelCase names failed in `compose_call` before
  signing (flop-labs/network#1176).
- Wallet balances are read from `AgentWallet.WalletFunds`; the `Wallets` record has no `balance`
  field, so every wallet read as `0.0`.
- `get_total_wallets` and `get_owner_wallet_count` read `AgentWallet.TotalWallets` and
  `AgentWallet.WalletCount` storage instead of RPC methods the node does not expose, whose
  `-32601` error was swallowed as `0`.
- `FlopClient.get_balance` and `get_account_info` read `System.Account` through
  `state_getStorage` instead of the unexposed `system_account` RPC. `AccountInfo.refcount`
  carries the runtime's `consumers` count.
